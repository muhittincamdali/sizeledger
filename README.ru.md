Укажите sizeledger файл `.ipa`, `.app` или `.xcarchive`, и он покажет, где находятся байты приложения:
по категориям, по framework и ресурсам, по языкам и по архитектурам CPU. Он только читает файлы: ничего не
собирает, не запускает, не загружает и не изменяет, а на macOS и на Linux работает одинаково.

<sub>Записано с настоящей команды (<code>node scripts/demo.mjs</code>) на
<a href="Fixtures/README.md">SampleShop 2.0</a> — приложении на SwiftUI, которое этот репозиторий собирает
для iOS Simulator. Вывод одинаков на Mac (Apple silicon) и в образах CI для Linux.</sub>

## Основные возможности

- **Одна таблица на всё приложение.** Основной исполняемый файл, framework и dylib, расширения
  приложения, App Clip, приложение для watch, локализации, asset catalog, подпись кода и всё остальное.
  Сумма по категориям всегда равна общему размеру.
- **Каждый framework и каждое расширение в отдельной строке**, а каждый язык `.lproj` суммируется по
  всему приложению и его framework.
- **Архитектурные слайсы каждого бинарника**: какие бинарники универсальные и сколько занимает каждый
  слайс; размеры сегментов и метаданные Swift есть в JSON.
- **Три размера по отдельности**: сумма файлов, оценка размера установки (целые блоки по 4 KiB, как их
  хранит APFS) и, для `.ipa`, сжатый размер. sizeledger не утверждает, что знает размер загрузки из
  App Store; [почему так](docs/guides/why-install-size-is-an-estimate.md).
- **И для людей, и для CI**: таблица в терминале, Markdown для pull request или сводки задания и
  JSON-отчёт со стабильным порядком ключей, который можно закоммитить, обработать через `jq` и сравнить.
- **Ещё и библиотека на Swift**: [SizeLedgerKit](https://muhittincamdali.github.io/sizeledger/) отдаёт тот
  же отчёт вашим собственным инструментам. Без зависимостей: чтение ZIP, декодер DEFLATE и парсер Mach-O
  входят в состав библиотеки.

## Быстрый старт

**1. Установите** (macOS или Linux с [Homebrew](https://brew.sh)):

```sh
brew install muhittincamdali/tap/sizeledger
```

Без Homebrew воспользуйтесь
[бинарником из релиза или соберите из исходников](#установка).

**2. Измерьте своё приложение.** Подойдёт любой вариант: экспортированный `.ipa`, `.app` из сборки или
`.xcarchive` из **Product › Archive**.

```sh
sizeledger analyze path/to/MyApp.ipa
```

**3. Прочитайте таблицу.** «By category» показывает, какой тип содержимого тяжёлый; «Largest items»
называет конкретные файлы, framework и папки; «Binaries» показывает, какие бинарники содержат больше одной
архитектуры. Примечания в конце сообщают, когда число нуждается в пояснении (например, сборка для
симулятора). Сохраните полный отчёт с помощью `--out size/main.json`, чтобы хранить его или сравнивать позже.

[Прочитайте свою первую разбивку](docs/guides/read-your-first-breakdown.md) — в руководстве настоящий
отчёт разбирается строка за строкой.

## Установка

| Способ                  | Команда                                                                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Homebrew (macOS, Linux) | `brew install muhittincamdali/tap/sizeledger`                                                                                                                                                                                         |
| Бинарник из релиза      | Скачайте `sizeledger-<version>-macos-universal.tar.gz` или `-linux-x86_64` / `-linux-aarch64` со страницы [Releases](https://github.com/muhittincamdali/sizeledger/releases), сверьте с `SHA256SUMS` и положите `sizeledger` в `PATH` |
| Из исходников           | `git clone https://github.com/muhittincamdali/sizeledger.git && cd sizeledger && swift build -c release` (бинарник будет в `.build/release/sizeledger`)                                                                               |
| Swift package           | `.package(url: "https://github.com/muhittincamdali/sizeledger", from: "0.1.5")`, product `SizeLedgerKit`                                                                                                                              |

Для сборки нужен Swift 6.2 или новее (на Mac — Xcode 26 или новее). Бинарники для Linux содержат
рантайм Swift и требуют glibc 2.35 или новее (Ubuntu 22.04, Debian 12 или новее).

## Использование

```text
sizeledger analyze <input> [--format tty|markdown|json] [--out <file>] [--top <n>] [--color auto|always|never] [--quiet]
                    [--max-files <n>] [--max-bytes <bytes>] [--max-ratio <ratio>] [--max-depth <n>]
```

| Параметр           | Что делает                                                                     |
| ------------------ | ------------------------------------------------------------------------------ |
| `<input>`          | Папка `.app`, файл `.ipa` или папка `.xcarchive`                               |
| `-f, --format`     | Что выводить: `tty` (по умолчанию, таблица), `markdown` или `json`             |
| `-o, --out <file>` | Дополнительно записывает JSON-отчёт в файл; недостающие папки создаются        |
| `--top <n>`        | Сколько элементов, языков и бинарников выводить (по умолчанию 10)              |
| `--color`          | `auto` включает цвета только в терминале и не включает, если задана `NO_COLOR` |
| `-q, --quiet`      | Ничего не выводит (вместе с `--out`)                                           |

Код завершения: `0` — отчёт создан; `2` — входные данные не удалось прочитать или отчёт не удалось
записать (причину сообщает одна строка в стандартном потоке ошибок); `64` — неверные параметры. Код `1`
зарезервирован для планируемой команды `budget`.

```sh
# Keep the report for later
sizeledger analyze build/MyApp.ipa --out size/main.json

# Markdown in a GitHub Actions job summary
sizeledger analyze build/MyApp.xcarchive --format markdown >> "$GITHUB_STEP_SUMMARY"

# The ten biggest files anywhere in the bundle (bytes and file name)
jq -r '[.tree | .. | objects | select(has("children") | not)] | sort_by(-.bytes) | .[:10][] | "\(.bytes)\t\(.name)"' size/main.json
```

Структура JSON описана в [статье DocC](https://muhittincamdali.github.io/sizeledger/documentation/sizeledgerkit/jsonlayout);
полные отчёты лежат в [Fixtures/snapshots](Fixtures/snapshots).

## Три размера

| Размер                                    | Что означает                                                                | Для SampleShop 2.0 |
| ----------------------------------------- | --------------------------------------------------------------------------- | ------------------ |
| Общий (`bytes`)                           | Сумма файлов — то, что показывает файловый менеджер                         | 8.75 MB            |
| Размер установки, оценка (`installBytes`) | Каждый файл, округлённый вверх до целых блоков по 4 KiB, как их хранит APFS | 8.80 MB            |
| Сжатый в `.ipa` (`compressedBytes`)       | Сколько файлы бандла занимают внутри архива; только для входного `.ipa`     | 2.72 MB            |

Ни один из них не равен размеру загрузки или установки из App Store: App Store адаптирует приложение под
конкретное устройство (thinning), шифрует бинарники и сжимает загрузку. Эти числа дают App Thinning Size
Report в Xcode и App Store Connect. sizeledger даёт те числа, которые можно получить только из файлов, на
любой машине и для каждой сборки.
[Почему размер установки — это оценка](docs/guides/why-install-size-is-an-estimate.md) объясняет это
подробно, а [Ограничения размера App Clip](docs/guides/app-clip-size.md) применяют это к App Clip.

## Как это тестируется

- **Сверка с `du`** — приёмочная проверка v0.1 — на двух версиях SampleShop, распакованных из `.ipa`. На
  Mac (Apple silicon, macOS 27.0.1, APFS) оценка размера установки в точности равна `du -sk`, а общий
  размер отличается от `du -A` не более чем на 0.16%; в контейнере Linux (swift:6.4.1-noble, aarch64)
  общий размер равен `du -b --apparent-size`, а оценка размера установки отличается от `du -sk` не более
  чем на 0.65% (там `du -sk` учитывает ещё и по 4 KiB на каждую папку). Тесты падают при расхождении
  больше 1% в обоих случаях.
- **Снапшоты**: JSON-, текстовый и Markdown-отчёты обеих версий закоммичены; одни и те же снапшоты
  проходят и на macOS, и на Linux.
- **Настоящее приложение**: SampleShop собирается с помощью `swiftc`, `actool` и `codesign`
  [скриптом](Fixtures/scripts/build-sample-app.sh) и запускается в симуляторе iOS 27.0:

    <picture><source media="(prefers-color-scheme: dark)" srcset="docs/media/sampleshop-ios27-simulator-dark.png"><source media="(prefers-color-scheme: light)" srcset="docs/media/sampleshop-ios27-simulator-light.png"><img src="docs/media/sampleshop-ios27-simulator-light.png" alt="SampleShop 2.0 в iOS 27 Simulator: баннер и список товаров с изображениями и ценами" width="240"></picture>

- **Ридеры, сверенные с эталонами**: декодер DEFLATE — с выводом zlib для блоков stored, fixed и dynamic;
  парсер Mach-O — на thin-, 32-битных, fat- и fat64-файлах; кроме того, ZIP64, повреждённые архивы и имена
  файлов с управляющими последовательностями терминала.

Всего 130 тестов, которые CI запускает на macOS и на Linux (x86_64 и arm64). Измерение SampleShop 2.0
в release-сборке, включая запуск процесса, заняло в медиане от 14.4 до 17.4 ms в трёх сериях по 21
запуску на Mac (Apple silicon), занятом другой работой (средняя нагрузка от 41 до 136); время зависит
от того, что ещё выполняется на машине. [scripts/bench.sh](scripts/bench.sh) повторяет это измерение.

## Ограничения

- Размеры — это локальные измерения. Размеры загрузки и установки в App Store зависят от thinning,
  шифрования и сжатия, которые выполняются на стороне Apple, поэтому sizeledger сообщает оценку и прямо
  об этом говорит.
- Asset catalog (`Assets.car`) учитываются как файлы; rendition внутри них пока не перечисляются
  (планируется в 0.8 через `assetutil` на macOS).
- Метаданные Swift — это размер секций `__swift5_*`, то есть нижняя граница: часть метаданных лежит в
  `__const`.
- Бандлы в стиле iOS (iOS, iPadOS, tvOS, watchOS, visionOS) классифицируются. `.app` для macOS с папкой
  `Contents/` измеряется, но её файлы попадают в «Other resources».
- `.ipa` с несколькими приложениями, зашифрованными записями, со сжатием, отличным от stored и DEFLATE,
  или с путём записи, содержащим компонент `..`, отклоняется с сообщением, а не угадывается.
- Чтобы добраться до заголовка Mach-O глубоко внутри сжатой записи `.ipa`, sizeledger распаковывает
  всё, что идёт перед ним, но хранит только окно в 32 KiB, поэтому специально подготовленная запись
  стоит времени, а не памяти: около 1 s на распакованный GB на Mac (Apple silicon).
- Входные данные не являются доверенными, поэтому подготовленный или повреждённый ввод не может
  исчерпать память, время или стек. sizeledger отклоняет ввод, в котором больше 500 000 файлов или
  путь вложен глубже 64 папок, `.ipa`, заявляющий больше 8 ГиБ несжатых байтов, и `.ipa` с записью,
  распаковывающейся более чем в 300 раз больше её хранимого размера (zip-бомба); поднять эти
  пределы можно с помощью `--max-files`, `--max-depth`, `--max-bytes` и `--max-ratio`.
  `--max-depth` можно поднять не выше 100, чтобы JSON-отчёт всегда можно было записать, а
  `--max-bytes` действует только для `.ipa`, поскольку папка не распаковывается. Повреждённые
  заголовки Mach-O или ZIP дают пометку "unreadable" или понятную ошибку с кодом выхода 2, но
  никогда не приводят к сбою. Повторяющийся путь записи учитывается один раз.
