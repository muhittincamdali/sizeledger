sizeledger에 `.ipa`, `.app` 또는 `.xcarchive`를 지정하면 앱의 바이트가 어디에 있는지 카테고리별, framework와
리소스별, 언어별, CPU 아키텍처별로 보여 줍니다. 파일을 읽기만 할 뿐 빌드, 실행, 업로드, 변경은 하지 않으며,
macOS와 Linux에서 똑같이 동작합니다.

## 주요 기능

- **앱 전체를 한 장의 표로.** 메인 실행 파일, framework와 dylib, 앱 extension, App Clip, watch 앱,
  현지화, asset catalog, 코드 서명, 그 밖의 모든 것. 카테고리의 합은 항상 전체 크기와 같습니다.
- **모든 framework와 extension을 각각 한 줄로** 보여 주며, 각 `.lproj` 언어는 앱과 그 framework 전체에서
  합산합니다.
- **모든 바이너리의 아키텍처 슬라이스**: 어떤 바이너리가 universal인지, 각 슬라이스가 얼마를 차지하는지
  보여 줍니다. 세그먼트 크기와 Swift metadata는 JSON에 들어 있습니다.
- **서로 구분한 세 가지 크기**: 파일 크기의 합, 설치 크기 추정치(APFS가 저장하는 방식대로 4 KiB 블록
  단위), 그리고 `.ipa`의 경우 압축 크기. sizeledger는 App Store의 다운로드 크기를 안다고 주장하지
  않습니다. [그 이유는 여기에서 확인하세요](docs/guides/why-install-size-is-an-estimate.md).
- **사람과 CI 모두를 위해**: 터미널 표, pull request나 작업 요약에 쓸 Markdown, 키 순서가 고정된 JSON
  리포트. JSON 리포트는 커밋하고, `jq`로 가공하고, 비교할 수 있습니다.
- **Swift 라이브러리로도**: [SizeLedgerKit](https://muhittincamdali.github.io/sizeledger/)을 사용하면 직접
  만든 도구에서도 같은 리포트를 얻을 수 있습니다. 의존성이 없습니다. ZIP 리더, DEFLATE 디코더, Mach-O
  파서가 라이브러리 안에 들어 있습니다.

## 빠른 시작

**1. 설치하기** ([Homebrew](https://brew.sh)를 쓰는 macOS 또는 Linux):

```sh
brew install muhittincamdali/tap/sizeledger
```

Homebrew를 쓰지 않는다면 [릴리스 바이너리를 사용하거나 소스에서 빌드](#설치)하세요.

**2. 앱 측정하기.** 다음 중 무엇이든 됩니다. 내보낸 `.ipa`, 빌드로 만든 `.app`, 또는
**Product › Archive**로 만든 `.xcarchive`입니다.

```sh
sizeledger analyze path/to/MyApp.ipa
```

**3. 표 읽기.** "By category"는 어떤 종류의 콘텐츠가 큰지 알려 주고, "Largest items"는 파일, framework,
폴더를 이름으로 보여 주며, "Binaries"는 아키텍처를 둘 이상 담은 바이너리를 보여 줍니다. 끝에 있는 주석은
숫자에 설명이 필요할 때(예: 시뮬레이터 빌드) 알려 줍니다. 전체 리포트를 보관하거나 나중에 비교하려면
`--out size/main.json`으로 저장하세요.

[첫 번째 분석 결과 읽기](docs/guides/read-your-first-breakdown.md)에서 실제 리포트를 한 줄씩 따라가며
설명합니다.

들어 있으며 glibc 2.35 이상(Ubuntu 22.04, Debian 12 또는 그 이후 버전)이 필요합니다.

## 사용법

```text
sizeledger analyze <input> [--format tty|markdown|json] [--out <file>] [--top <n>] [--color auto|always|never] [--quiet]
```

| 옵션               | 설명                                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| `<input>`          | `.app` 폴더, `.ipa` 파일 또는 `.xcarchive` 폴더                             |
| `-f, --format`     | 출력 형식: `tty`(기본값, 표), `markdown` 또는 `json`                        |
| `-o, --out <file>` | JSON 리포트를 파일로도 저장합니다. 없는 폴더는 만들어 줍니다                |
| `--top <n>`        | 나열할 항목, 언어, 바이너리의 개수(기본값 10)                               |
| `--color`          | `auto`는 터미널에서만 색을 쓰며, `NO_COLOR`가 설정되어 있으면 쓰지 않습니다 |
| `-q, --quiet`      | 아무것도 출력하지 않습니다(`--out`과 함께 사용)                             |

종료 상태: 리포트를 만들었으면 `0`, 입력을 읽지 못했거나 리포트를 쓰지 못했으면 `2`(표준 오류의 한 줄이
이유를 알려 줍니다), 잘못된 옵션이면 `64`입니다. `1`은 계획된 `budget` 명령을 위해 남겨 두었습니다.

```sh
# Keep the report for later
sizeledger analyze build/MyApp.ipa --out size/main.json

# Markdown in a GitHub Actions job summary
sizeledger analyze build/MyApp.xcarchive --format markdown >> "$GITHUB_STEP_SUMMARY"

# The ten biggest files anywhere in the bundle (bytes and file name)
jq -r '[.tree | .. | objects | select(has("children") | not)] | sort_by(-.bytes) | .[:10][] | "\(.bytes)\t\(.name)"' size/main.json
```

JSON 구조는 [DocC 문서](https://muhittincamdali.github.io/sizeledger/documentation/sizeledgerkit/jsonlayout)에
설명되어 있으며, [Fixtures/snapshots](Fixtures/snapshots)에 전체 리포트가 있습니다.

## 세 가지 크기

| 크기                                     | 의미                                                              | SampleShop 2.0의 값 |
| ---------------------------------------- | ----------------------------------------------------------------- | ------------------- |
| 합계(`bytes`)                            | 파일 크기를 모두 더한 값으로, 파일 관리자가 보여 주는 값          | 8.75 MB             |
| 설치 크기, 추정치(`installBytes`)        | APFS가 저장하는 방식대로 각 파일을 4 KiB 블록 단위로 올림한 값    | 8.80 MB             |
| `.ipa` 안의 압축 크기(`compressedBytes`) | 번들의 파일이 아카이브 안에서 차지하는 크기. `.ipa` 입력에만 해당 | 2.72 MB             |

이 중 어느 것도 App Store의 다운로드 크기나 설치 크기가 아닙니다. App Store는 기기별로 앱을 thinning하고,
바이너리를 암호화하고, 다운로드를 압축합니다. 그 숫자는 Xcode의 App Thinning Size Report와 App Store
Connect에서 알 수 있습니다. sizeledger는 파일만으로 어떤 컴퓨터에서든, 모든 빌드에 대해 얻을 수 있는 숫자를
보여 줍니다. [설치 크기가 추정치인 이유](docs/guides/why-install-size-is-an-estimate.md)에서 자세히 설명하고,
[App Clip 크기 제한](docs/guides/app-clip-size.md)에서는 이를 App Clip에 적용합니다.

## 테스트 방법

- **`du`와의 비교**는 v0.1의 인수 검사이며, `.ipa`에서 풀어낸 SampleShop 두 버전으로 수행합니다. Mac(Apple
  silicon, macOS 27.0.1, APFS)에서는 설치 크기 추정치가 `du -sk`와 정확히 같고 합계는 `du -A`와 0.16% 이내로
  일치합니다. Linux 컨테이너(swift:6.4.1-noble, aarch64)에서는 합계가 `du -b --apparent-size`와 같고 설치
  크기 추정치는 `du -sk`와 0.65% 이내로 일치합니다(그곳의 `du -sk`는 폴더마다도 4 KiB를 셉니다). 두 환경
  모두 차이가 1%를 넘으면 테스트가 실패합니다.
- **스냅샷**: 두 버전의 JSON, 텍스트, Markdown 리포트를 커밋해 두었으며, 같은 스냅샷이 macOS와 Linux에서
  모두 통과합니다.
- **실제 앱**: SampleShop은 [스크립트](Fixtures/scripts/build-sample-app.sh)가 `swiftc`, `actool`,
  `codesign`으로 빌드하며 iOS 27.0 시뮬레이터에서 실행됩니다.

    <picture><source media="(prefers-color-scheme: dark)" srcset="docs/media/sampleshop-ios27-simulator-dark.png"><source media="(prefers-color-scheme: light)" srcset="docs/media/sampleshop-ios27-simulator-light.png"><img src="docs/media/sampleshop-ios27-simulator-light.png" alt="iOS 27 Simulator의 SampleShop 2.0: 배너와, 이미지와 가격이 있는 상품 목록" width="240"></picture>

- **기준과 대조한 리더**: DEFLATE 디코더는 stored, fixed, dynamic 블록에 대해 zlib의 출력과, Mach-O
  파서는 thin, 32비트, fat, fat64 파일에서 대조했습니다. ZIP64, 손상된 아카이브, 터미널 이스케이프
  시퀀스가 들어 있는 파일 이름도 확인합니다.

테스트는 모두 95개이며, CI가 macOS와 Linux(x86_64와 arm64)에서 실행합니다. release 빌드로 Mac(Apple
silicon)에서 SampleShop 2.0을 측정하는 데는 21회 실행의 중앙값으로 11.4 ms가 걸립니다.

## 제한 사항

- 크기는 로컬에서 측정한 값입니다. App Store의 다운로드 크기와 설치 크기는 Apple 쪽에서 이루어지는
  thinning, 암호화, 압축에 따라 달라지므로 sizeledger는 추정치를 보고하고 그렇다고 밝힙니다.
- asset catalog(`Assets.car`)는 파일로 계산하며, 그 안의 rendition은 아직 나열하지 않습니다(macOS의
  `assetutil`을 통해 0.8에서 제공할 계획입니다).
- Swift metadata는 `__swift5_*` 섹션의 크기이며 하한값입니다. 일부 metadata는 `__const`에 있습니다.
- iOS 방식의 번들(iOS, iPadOS, tvOS, watchOS, visionOS)은 분류됩니다. `Contents/` 폴더가 있는 macOS
  `.app`은 측정되지만, 그 파일은 "Other resources" 아래에 들어갑니다.
- 앱이 둘 이상 들어 있거나, 암호화된 항목이 있거나, stored와 DEFLATE 외의 압축을 쓰거나, 항목 경로에
  `..` 구성 요소가 있는 `.ipa`는 추측하지 않고 메시지와 함께 거부합니다.
- 압축된 `.ipa` 항목 깊숙한 곳의 Mach-O 헤더를 읽기 위해 sizeledger는 그 앞의 모든 내용을 풀지만 32 KiB 창만 유지합니다. 따라서 조작된 항목은
  메모리가 아니라 시간을 소비하며, Mac(Apple silicon)에서 풀린 1 GB당 약 1 s가 걸립니다.
