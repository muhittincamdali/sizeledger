sizeledger に `.ipa`、`.app`、`.xcarchive` を指定すると、アプリのバイトがどこにあるかを、カテゴリ別、framework とリソース別、言語別、CPU アーキテクチャ別に表示します。ファイルを読み取るだけで、ビルド、実行、アップロード、変更は一切行わず、macOS と Linux のどちらでも同じように動作します。

<picture><source media="(prefers-color-scheme: dark)" srcset="docs/media/demo-analyze-dark.svg"><source media="(prefers-color-scheme: light)" srcset="docs/media/demo-analyze-light.svg"><img src="docs/media/demo-analyze-light.svg" alt="SampleShop 2.0 に対する sizeledger analyze の出力: 21 ファイルで 8.75 MB、インストールサイズの推定 8.80 MB、圧縮後 2.72 MB。catalog.json がアプリの 70.8%、Assets.car が 18.1%。7 言語。x86_64 と arm64 のスライスを持つ universal バイナリが 3 つ"></picture>

<sub>実際のコマンド (<code>node scripts/demo.mjs</code>) の出力を、<a href="Fixtures/README.md">SampleShop 2.0</a> に対して記録したものです。SampleShop 2.0 は、このリポジトリが iOS Simulator 向けにビルドする SwiftUI アプリです。出力は Mac (Apple silicon) でも Linux の CI イメージでも同じです。</sub>

## 主な特長

- **アプリ全体を 1 つの表で。** メイン実行ファイル、framework と dylib、App Extension、App Clip、watch アプリ、ローカライズ、asset catalog、コード署名、その他すべて。カテゴリの合計は常に総サイズと一致します。
- **framework と extension をそれぞれ 1 行で**表示し、各 `.lproj` の言語は、アプリとその framework 全体で合算します。
- **すべてのバイナリのアーキテクチャスライス**: どのバイナリが universal で、各スライスがどれだけの容量を占めるかを示します。セグメントのサイズと Swift metadata は JSON に含まれます。
- **区別して扱う 3 つのサイズ**: ファイルの合計、インストールサイズの推定値 (APFS の保存方式に合わせた、4 KiB 単位のブロック)、そして `.ipa` の場合は圧縮サイズ。sizeledger は App Store のダウンロードサイズを知っているとは主張しません。[理由はこちら](docs/guides/why-install-size-is-an-estimate.md)。
- **人にも CI にも**: ターミナル向けの表、pull request やジョブサマリー向けの Markdown、キーの順序が固定された JSON レポート。JSON はコミットしたり、`jq` で処理したり、比較したりできます。
- **Swift ライブラリとしても**: [SizeLedgerKit](https://muhittincamdali.github.io/sizeledger/) を使えば、自分のツールで同じレポートを得られます。依存関係はありません。ZIP リーダー、DEFLATE デコーダー、Mach-O パーサーはライブラリ自身に含まれています。

## クイックスタート

**1. インストールする** ([Homebrew](https://brew.sh) を使った macOS または Linux):

```sh
brew install muhittincamdali/tap/sizeledger
```

Homebrew を使わない場合は、[リリースのバイナリを使うか、ソースからビルド](#インストール)してください。

**2. アプリを測定する。** 次のどれでも使えます。書き出した `.ipa`、ビルドで得た `.app`、または **Product › Archive** で作成した `.xcarchive` です。

```sh
sizeledger analyze path/to/MyApp.ipa
```

**3. 表を読む。** "By category" はどの種類のコンテンツが重いかを示し、"Largest items" はファイル、framework、フォルダを名前で挙げ、"Binaries" は複数のアーキテクチャを含むバイナリを示します。末尾の注記は、数値に補足が必要な場合 (たとえばシミュレーター向けビルド) に表示されます。完全なレポートを保存して後で比較するには、`--out size/main.json` を付けてください。

[最初の内訳を読む](docs/guides/read-your-first-breakdown.md)では、実際のレポートを 1 行ずつ解説しています。

## インストール

| 方法                    | コマンド                                                                                                                                                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Homebrew (macOS、Linux) | `brew install muhittincamdali/tap/sizeledger`                                                                                                                                                                                                 |
| リリースのバイナリ      | [Releases](https://github.com/muhittincamdali/sizeledger/releases) から `sizeledger-<version>-macos-universal.tar.gz`、または `-linux-x86_64` / `-linux-aarch64` をダウンロードし、`SHA256SUMS` で検証して、`sizeledger` を `PATH` に置きます |
| ソースから              | `git clone https://github.com/muhittincamdali/sizeledger.git && cd sizeledger && swift build -c release` (バイナリは `.build/release/sizeledger` です)                                                                                        |
| Swift package           | `.package(url: "https://github.com/muhittincamdali/sizeledger", from: "0.1.2")`、product は `SizeLedgerKit`                                                                                                                                   |

ビルドには Swift 6.2 以降が必要です (Mac では Xcode 26 以降)。Linux 向けのリリースバイナリには Swift ランタイムが含まれており、glibc 2.35 以降 (Ubuntu 22.04、Debian 12 以降) が必要です。

## 使い方

```text
sizeledger analyze <input> [--format tty|markdown|json] [--out <file>] [--top <n>] [--color auto|always|never] [--quiet]
                    [--max-files <n>] [--max-bytes <bytes>] [--max-ratio <ratio>] [--max-depth <n>]
```

| オプション         | 動作                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| `<input>`          | `.app` フォルダ、`.ipa` ファイル、または `.xcarchive` フォルダ                 |
| `-f, --format`     | 出力する形式: `tty` (デフォルト、表)、`markdown`、`json`                       |
| `-o, --out <file>` | JSON レポートをファイルにも書き出します。存在しないフォルダは作成されます      |
| `--top <n>`        | 一覧に表示する項目、言語、バイナリの数 (デフォルトは 10)                       |
| `--color`          | `auto` はターミナルでのみ色を付け、`NO_COLOR` が設定されている場合は付けません |
| `-q, --quiet`      | 何も出力しません (`--out` と併用)                                              |

終了ステータス: レポートを作成できた場合は `0`、入力を読み取れない場合やレポートを書き込めない場合は `2` (理由は標準エラー出力の 1 行で示されます)、無効なオプションの場合は `64` です。`1` は、計画中の `budget` コマンドのために確保してあります。

```sh
# Keep the report for later
sizeledger analyze build/MyApp.ipa --out size/main.json

# Markdown in a GitHub Actions job summary
sizeledger analyze build/MyApp.xcarchive --format markdown >> "$GITHUB_STEP_SUMMARY"

# The ten biggest files anywhere in the bundle (bytes and file name)
jq -r '[.tree | .. | objects | select(has("children") | not)] | sort_by(-.bytes) | .[:10][] | "\(.bytes)\t\(.name)"' size/main.json
```

JSON の構造は [DocC の記事](https://muhittincamdali.github.io/sizeledger/documentation/sizeledgerkit/jsonlayout)で説明しています。完全なレポートは [Fixtures/snapshots](Fixtures/snapshots) にあります。

## 3 つのサイズ

| サイズ                                    | 意味                                                                      | SampleShop 2.0 の場合 |
| ----------------------------------------- | ------------------------------------------------------------------------- | --------------------- |
| 合計 (`bytes`)                            | ファイルの合計。ファイルマネージャーに表示される値                        | 8.75 MB               |
| インストールサイズ、推定 (`installBytes`) | APFS の保存方式に合わせ、各ファイルを 4 KiB ブロックの単位に切り上げた値  | 8.80 MB               |
| `.ipa` 内の圧縮サイズ (`compressedBytes`) | バンドル内のファイルがアーカイブ内で占める容量。`.ipa` を入力した場合のみ | 2.72 MB               |

どれも App Store のダウンロードサイズやインストールサイズではありません。App Store はデバイスごとにアプリをスライス (thinning) し、バイナリを暗号化し、ダウンロードを圧縮します。それらの数値は、Xcode の App Thinning Size Report と App Store Connect で確認できます。sizeledger が示すのは、ファイルだけから、どのマシンでも、すべてのビルドで得られる数値です。[インストールサイズが推定値である理由](docs/guides/why-install-size-is-an-estimate.md)で詳しく説明しており、[App Clip のサイズ制限](docs/guides/app-clip-size.md)では、それらを App Clip に当てはめています。

## テスト方法

- **`du` との照合**: v0.1 の受け入れ確認として、`.ipa` から展開した SampleShop の 2 つのバージョンで行っています。Mac (Apple silicon、macOS 27.0.1、APFS) では、インストールサイズの推定値は `du -sk` と完全に一致し、合計は `du -A` との差が 0.16% 以内です。Linux コンテナー (swift:6.4.1-noble、aarch64) では、合計は `du -b --apparent-size` と一致し、インストールサイズの推定値は `du -sk` との差が 0.65% 以内です (そこでは `du -sk` がフォルダごとにも 4 KiB を数えます)。どちらの環境でも、差が 1% を超えるとテストは失敗します。
- **スナップショット**: 両バージョンの JSON、テキスト、Markdown のレポートをコミットしてあり、同じスナップショットが macOS と Linux の両方で通ります。
- **実際のアプリ**: SampleShop は、[スクリプト](Fixtures/scripts/build-sample-app.sh)が `swiftc`、`actool`、`codesign` でビルドし、iOS 27.0 のシミュレーターで動作します。

    <picture><source media="(prefers-color-scheme: dark)" srcset="docs/media/sampleshop-ios27-simulator-dark.png"><source media="(prefers-color-scheme: light)" srcset="docs/media/sampleshop-ios27-simulator-light.png"><img src="docs/media/sampleshop-ios27-simulator-light.png" alt="iOS 27 Simulator 上の SampleShop 2.0: バナーと、画像と価格付きの商品リスト" width="240"></picture>

- **リファレンスと照合したリーダー**: DEFLATE デコーダーは stored、fixed、dynamic の各ブロックについて zlib の出力と、Mach-O パーサーは thin、32 ビット、fat、fat64 のファイルで照合しています。ZIP64、破損したアーカイブ、ターミナルのエスケープシーケンスを含むファイル名も確認しています。

テストは全部で 124 件あり、CI が macOS と Linux (x86_64 と arm64) で実行します。SampleShop 2.0 の測定にかかる時間は、release ビルドを使った Mac (Apple silicon) で、21 回の実行の中央値が 10.5 ms です (プロセスの起動を含みます)。[scripts/bench.sh](scripts/bench.sh) で同じ測定を再現できます。

## 制限事項

- サイズはローカルでの測定値です。App Store のダウンロードサイズとインストールサイズは、Apple 側で行われる thinning、暗号化、圧縮に左右されるため、sizeledger は推定値を報告し、そのことを明示します。
- asset catalog (`Assets.car`) はファイルとして数えます。中の rendition はまだ一覧表示されません (macOS の `assetutil` を使って 0.8 で対応予定です)。
- Swift metadata は `__swift5_*` セクションのサイズで、下限値です。一部の metadata は `__const` にあります。
- iOS 形式のバンドル (iOS、iPadOS、tvOS、watchOS、visionOS) は分類されます。`Contents/` フォルダを持つ macOS の `.app` は測定されますが、そのファイルは "Other resources" に入ります。
- 複数のアプリを含む `.ipa`、暗号化されたエントリを含む `.ipa`、stored と DEFLATE 以外の圧縮を使う `.ipa`、エントリのパスに `..` を含む `.ipa` は、推測で処理せず、メッセージを表示して拒否します。
- 圧縮された `.ipa` エントリの奥にある Mach-O ヘッダーを読むため、sizeledger はその手前をすべて展開しますが、保持するのは 32 KiB のウィンドウだけです。そのため細工されたエントリが消費するのはメモリではなく時間で、Mac (Apple silicon) では展開 1 GB あたり約 1 s です。
- 入力は信頼できないため、細工または破損した入力でもメモリ・時間・スタックを使い尽くすことはありません。
  sizeledger は次の入力を拒否します: ファイルが 500,000 を超える、パスが 64 フォルダより深くネストされている、
  `.ipa` が宣言する非圧縮バイトが 8 GiB を超える、または `.ipa` エントリが格納サイズの 300 倍を超えて展開される
  （zip 爆弾）。これらは `--max-files`、`--max-depth`、`--max-bytes`、`--max-ratio` で引き上げられます。
  JSON レポートを常に書き出せるよう `--max-depth` の上限は 100 で、フォルダは展開しないため `--max-bytes` は
  `.ipa` にのみ適用されます。壊れた Mach-O や ZIP ヘッダーは "unreadable" の注記か終了ステータス 2 の明確な
  エラーになり、クラッシュすることはありません。重複するエントリパスは一度だけ数えられます。
